GUIA-DOTNET — Parte 5: o GitHub confere o código

v1.0 · 09/10/2026 (S15) · Entradas 5.1–5.3. Complementa a Parte 4 (o build cobra as convenções): agora quem roda o build é uma máquina do GitHub, a cada push e PR.

5.1 CI básico com GitHub Actions

Problema: a main ficou quebrada (CS8604) sem ninguém perceber. Confiar na memória não escala.

Solução: um workflow em .github/workflows/ci.yml que, a cada push e PR para a main, instala o .NET 10, compila e roda os testes numa máquina limpa.

Termo O que é
Workflow arquivo .yml com o "quando" e o "o quê"
Job / Runner bloco de trabalho / a máquina que o executa
Step passo: uses (ação pronta) ou run (comando)
Check / Annotation semáforo no PR / mensagem de erro anexada 
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

permissions:
  contents: read

jobs:
  build-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-dotnet@v6
        with:
          dotnet-version: 10.0.x
      - run: dotnet build Norte.slnx
      - run: dotnet test Norte.slnx --no-build
Linha Sem ela
on: pull_request o PR não é conferido antes do merge
permissions: contents: read o workflow fica com permissões mais largas que o necessário
actions/checkout o runner está vazio; o build não acha a solution
actions/setup-dotnet SDK errado ou ausente; o build quebra por motivo alheio ao código
dotnet test --no-build sem teste, o check só diz que compila

Pontos obrigatórios: pasta .github/workflows/ na raiz; nome do arquivo livre. Versões das ações fixadas (@v7, @v6).

Preço: ~30 s a mais por PR; arquivo para manter; ubuntu-latest muda sozinho (aviso: migra para o Ubuntu 26 a partir de 19/10/2026 — decidir entre ubuntu-latest e ubuntu-24.04).

Limite importante: sem proteção de branch, o botão de merge continua clicável com o check vermelho. O CI avisa; não impede. (Proteção de branch em repositório privado: a conferir no plano.)

Prova de que o CI funciona = vê-lo falhar: PR descartável que remove o ! de Sku no Executar → vermelho com a annotation CS8604.

5.2 Mover um commit para outra branch e as três cópias de uma branch

Cenário: o commit caiu na main local, à frente do servidor.

git switch -c feat/ci-basico       # a nova branch nasce com o commit
git branch -f main origin/main     # a main local volta ao que o servidor tem
Cópia Onde Como apagar
Servidor GitHub "Delete branch" no PR
Local seu computador git branch -d (só se mesclada) · -D (força)
origin/<nome> cache local do servidor git fetch --prune

Apagar no GitHub não apaga a local. Opcional: git config --global fetch.prune true.

  4. Por que um PR descartável com erro de propósito prova mais que um PR verde?

Respostas

Mostrar respostas
  1. Está vazio; o actions/checkout.
  2. .github/workflows/ na raiz; o nome do arquivo é livre.
  3. Nada: sem proteção de branch, o botão continua clicável.
  4. Mostra o CI reprovando um erro real; verde sozinho não prova que ele sabe falhar.
  5. Ex.: ~30 s a mais por PR; ubuntu-latest muda sozinho e pode quebrar o CI sem o código mudar.
  6. Na branch local e em origin/<nome> até o fetch --prune.
  7. -d só apaga se já mesclada; -D força.
