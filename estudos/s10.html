3. Conceitos (resumo; o detalhe está no guia)

3.1 Program.cs em duas fases → 1.4

Como era Como é agora O que mudou
Startup.ConfigureServices(services) builder.Services.Add... antes do Build() Mesma coleção de DI, outro lugar
Startup.Configure(app, env) app.Map... / app.Use... depois do Build() Mesmo pipeline; env virou app.Environment
A divisão era garantida pelos dois métodos A divisão é a linha builder.Build() O compilador não impede registrar depois; o erro só aparece na execução

O seu experimento: mover AddCatalogo() para depois do Build() não deu erro porque o AddCatalogo ainda está vazio: a exceção só acontece quando algo é adicionado à coleção. Com AddProblemDetails() depois do Build(), a aplicação não sobe: InvalidOperationException: The service collection cannot be modified because it is read-only.

3.2 Controller → Minimal API → 1.9

Controller Minimal API O que mudou
[Route("catalogo")] na classe app.MapGroup("/catalogo") O prefixo vira um objeto (o grupo), não um atributo
[HttpGet("status")] no método grupo.MapGet("/status", ...) Verbo e rota numa chamada só
Método de ação dentro de uma classe Um delegate: lambda ou método Não precisa de classe nem de ControllerBase
AddControllers() + MapControllers() descobrem as classes por reflexão Cada Map... registra explicitamente Nada é descoberto: sem app.MapPedidos(), a rota não existe (404)

3.3 Métodos de extensão → 1.7

Método estático comum Método de extensão O que mudou
Registrar(IServiceCollection services) AddPedidos(this IServiceCollection services) Só o this no primeiro parâmetro
PedidosSetup.Registrar(builder.Services); builder.Services.AddPedidos(); Parece método da própria coleção
— using Norte.Pedidos; no arquivo que chama Sem ele: CS1061

3.4 Monolito modular: um processo só → 1.2

Tipo de bug num módulo O que acontece
Exceção dentro de uma requisição Só aquela requisição recebe 500; os outros módulos seguem
Bug que derruba o processo (memória, StackOverflowException, thread de fundo) Todos os módulos caem: são DLLs no mesmo processo

Módulos são isolados no código, não em execução. Isolar falha e deploy é o que microsserviços resolvem (M7), ao custo de rede e operação distribuída.

3.5 Módulo × funcionalidade × departamento → 1.12

Departamento Módulo Funcionalidade
É pessoas no organograma regras que valem juntas + dados próprios uma ação
Gramática área substantivo (assunto) verbo
Exemplo Comercial Pedidos, Precificacao, Vendas CriarPedido
Critério organograma a mesma palavra segue regra diferente? caso de uso

"Comercial" não é módulo: dentro dele, pedido muda, venda não muda, tabela de preço tem vigência. Nome igual a departamento é permitido (Financeiro), mas o motivo tem que ser a regra.

4. Termos da sessão

  • Duas fases do Program.cs: registrar serviços (antes do Build()) → ligar pipeline e rotas (depois).
  • MapGroup: prefixo + configuração comum para um conjunto de endpoints.
  • Delegate do endpoint: a lambda ou o método que responde à rota.
  • Solution folder: pasta virtual da solution; não existe no disco.
  • CLAUDE.md: contexto do repositório para o Claude Code.
  • Sobra de modelo: nome do código copiado que não foi trocado (PedidosCatalogo).

Respostas

Mostrar respostas
  1. AddPedidos() antes do Build(); MapPedidos() depois. Compila, porque para o compilador é uma chamada válida. O erro aparece na execução, na subida: InvalidOperationException (coleção somente leitura). A aplicação não sobe.
  2. grupo.MapGet("/status", ...) dentro de MapPedidos(), com o grupo "/pedidos"; e app.MapPedidos(); no Program.cs. Sem a chamada no Program.cs, o MapGet nunca roda e a rota não existe: 404.
  3. O Pedidos cai junto. Os módulos são DLLs no mesmo processo: se o processo morre, todos morrem. Monolito modular isola no código, não em execução.
  4. "A mesma palavra segue regras diferentes?" Pedido muda até ser convertido; venda nunca muda (correção vira devolução). Regras diferentes → módulos diferentes (Pedidos × Vendas). O departamento não decide.
  5. Não existe: é uma solution folder (virtual). Jeito seguro: dotnet new classlib -n Norte.Estoque -o src/Modulos/Estoque/Norte.Estoque e dotnet sln Norte.slnx add src/Modulos/Estoque/Norte.Estoque/Norte.Estoque.csproj.
