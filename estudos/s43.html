ESTUDO S43 — Organização dos testes do Norte

Material de estudo da sessão S43 (09/11/2026). Tempo líquido de estudo: 4h55 (14:48 a 21:58, pausa 18:00–20:15).

1. Objetivo e resultado

Objetivo: organizar os testes do Norte para que exista um "modelo" correto e os testes futuros já nasçam certos. Só os testes mudam (nada em src/); cada passo é uma branch e um PR pequeno; a régua de sucesso é 309 testes verdes (2 Api + 69 Catálogo + 81 Clientes + 92 Pedidos + 65 Representantes).

Resultado: Passos 0 a 3 entregues e parte do Passo 4 (PRs #107 a #114, todos mesclados, CI verde, 309 testes em todos).

Passo O que foi feito

2. Mapa dos níveis

  • Nível 1 — Gerar dados: Dados.* no lugar de literais e helpers repetidos.
  • Nível 2 — Subir o ambiente: uma fábrica base (Template Method) em vez de cinco cópias.
  • Nível 3 — Falar HTTP: métodos de extensão para o cabeçalho If-Match.
  • Nível 4 — Nomear e organizar: sufixo Tests, pastas, verbos dos métodos (próximas sessões).

3. Conceitos (de-para)

Antes Depois Por quê
ProximoCpf(), Guid como e-mail, SKUs locais Dados.Cpf(), Dados.Email(), Dados.Sku() Um só lugar para gerar dado válido e único
5 fábricas com Testcontainers copiado PostgresFabricaBase Subir o Postgres é igual; só migrar muda
Helper privado de PUT com If-Match em cada classe cliente.PutComIfMatchAsync(...) Escrito uma vez, usado por todos

Regra "o valor é o assunto do teste?" Se o valor é o que o teste verifica (linha de TheoryData, teste de domínio, duplicado, maiúsculas), o literal fica. Se é só um dado qualquer para o teste rodar, usa Dados.*.

Template Method — a base define o esqueleto (InitializeAsync sobe o contêiner e chama MigrarAsync), e cada fábrica preenche só o que muda: MigrarAsync (abstrato), Ambiente (virtual, "Testing") e ConfigurarServicos (virtual).

Método de extensão — this HttpClient cliente faz o método aparecer em qualquer HttpClient. A pasta Extensions/ usa namespace igual à pasta, e cada csproj consumidor declara um <Using>.

4. Termos

  • Fábrica de teste: WebApplicationFactory<Program> que sobe a API de verdade para os testes.
  • Fixture (IClassFixture): objeto criado uma vez por classe de teste e compartilhado.
  • ETag / If-Match: controle de concorrência otimista; o cliente devolve o ETag que recebeu.
  • IsTestProject=false: impede que o dotnet test trate uma biblioteca que referencia xunit como projeto de teste.
  • Central package management: versões dos pacotes em um só arquivo.

5. Dúvidas que apareceram

  • ConfigureLogging e services.AddLogging são equivalentes? Sim, é o mesmo registro.
  • Por que a fábrica da Api migra com o próprio DbContext em vez de Services? Porque o seed de Development roda ao iniciar a API; usar Services iniciaria a API antes do banco estar migrado.
  • Por que o \s do Ctrl+H do Visual Studio não pegou 6 das 8 ocorrências? Porque \s não atravessa quebra de linha; é preciso \n.

6. Divergências e decisões

  • Parâmetro caminho em vez de uri (regra CA1054 quebra o build).
  • Os testes de If-Match ausente ou malformado ("abc") ficam montados à mão: o cabeçalho errado é o assunto do teste.
  • A pasta Extensions/ nasce já pensando em mais extensões (cadastros por módulo).

9. Perguntas de recuperação

  1. Por que o projeto compartilhado precisou de IsTestProject=false?
RespostaPorque ele referencia `xunit`; o `dotnet test Norte.slnx` o tratava como projeto de teste e o testhost abortava (BouncyCastle ausente no manifesto de dependências).
  1. O que cada fábrica ainda implementa depois da base?
Resposta`MigrarAsync` (obrigatório), e opcionalmente `Ambiente` e `ConfigurarServicos`.
  1. Quando um literal deve continuar no teste em vez de virar Dados.*?
RespostaQuando o valor é o assunto do teste (TheoryData, domínio, duplicidade, maiúsculas).
  1. Por que a regex do Visual Studio achou só parte das ocorrências?
Resposta`\s` não atravessa quebra de linha; é preciso `\n` explícito.
  1. Como um teste perdido passou despercebido, e como evitar?
RespostaO CI ficou verde porque um teste a menos não falha; evita-se contando os testes (309 esperados) e comparando [Fact]/[Theory] antes e depois.
